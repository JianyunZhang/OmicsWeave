# OmicsWeave 候选发现、结果交付与中文编码改进计划

**P0 实施更新（2026-11-19）**　统一入口现已支持 `--results-dir`、运行级 Excel 摘要及 JSON 索引，以及用单组学和整合 ID 续跑。交付位于 `<结果根>/_deliveries/<实验 ID>/<交付 ID>/`，以便已有工具继续按实验目录枚举原有结果包。DIO 和 GLP-1RA 均有课题根目录下的 `run_analysis.py`，DIO 图件与关键表写入该次交付。模式与已知输入前提进入预检，标准 TSV 采用带 BOM 的 UTF-8；合成示例使用有实际输入的逆转模式。下文的现状和数据统计描述 11 月 18 日评估时的版本。[标准流程与参数](../../README.md) · [本地课题启动方式](../../local/README.md)

面板产出（矩阵 XLSX、分流与检验表，矩阵、分流、示踪剂覆盖图件）复制到交付目录的 `panels/<面板>/<组织>/`，`summary.xlsx` 的「面板结果」链接到这些副本。续跑沿用已有结果包前核对其登记的输入：改过 `panels.yaml` 后沿用旧整合包会被拒绝，需从 integrate 重跑；只改 `experiment.yaml` 的 `integration` 一节时单组学包仍可沿用。

评估日期为 2026-11-18。范围为当前工作树（HEAD `6dc8a3f`）的统一 Python 入口、两个本地 DIO 课题及其已有结果包。本次复核读取真实结果，执行流程预检、定向测试和一次隔离的关键结果导出。两个课题均未从原始数据重新计算。

## 现有流程能回答哪些研究问题

| 研究问题 | 目前如何产生结果 | 决定搜索范围的因素 |
|---|---|---|
| 哪些测得的基因、蛋白、代谢物或通量有差异？ | 各组学 runner 按实验比较和组织分析经质控的特征，完整差异表可筛出预期外特征。 | 输入测量、分组与比较、过滤、样本量、效应量与多重校正。无需逐个指定目标。 |
| 哪些已注释通路出现预期外的变化？ | 单组学 ORA 或预排序 GSEA 遍历可检验的集合。`pathway_convergence` 读取富集结果，在同一组织和比较中融合至少两个组学均有记录的通路，另外给出方向与交集。 | 基因集库、代谢物注释、可检测背景及集合大小。代谢组默认限于代谢通路，并排除 overview 图。单层结果仍可在各组学表中查阅。 |
| 哪些反应值得追踪？ | `flux_anchored` 从 MFA 结果出发关联其他组学。`reaction_dossier` 默认从反应映射与主来源合并 MFA 结果中反应 ID 的并集建立档案；在各组织、比较内按通量结论等级、同向证据轴、复现、完整度和效应量排序。 | `reactions`、`tissues` 可选，填写后会缩小档案范围。模型覆盖和映射质量影响可解释程度，缺失、不可检验和方向冲突应在候选表保留。 |
| 如何检验某个代谢物分流、带方向的模块，或逐个反应出图？ | 在 `panels.yaml` 中声明反应分段、分支节点与出口、正负成员等。程序可补出网络中的代谢物、生成面板矩阵、分流、模块与相应图件。 | 这些读数依赖面板定义。面板若声明 `expected_tracers`，还会影响相关反应的通量证据判定。DIO 的 PPAR、胆固醇摘要另有课题脚本中的手工基因清单。 |

**目前可以发现研究者事先未点名的候选。** 全局结果所用的生物学关系仍来自测得的数据、通路库和模型。反应档案的等级评估、通路富集，以及从观测矩阵推导未知相互作用，是三种不同的研究任务。现有统一流程尚未提供经验证的未知反应或无先验通路重建能力。

两包的 `reaction_assessment.parquet`、`axis_assessment.parquet`、`pathway_fusion.parquet` 分别取得相同的 SHA-256。四个面板均未声明预期示踪剂。面板以外的 `RPI_c` 在心脏 `HSD_vs_LFD` 中排第 1，通量证据为 L2（提示性），机制列为 `unresolved`。实际表中 L2 有 72 行，L1 有 19 行，L0 有 4,147 行，L3 为 0。排名的解释单位是同一组织、同一比较，不能据此指定全项目的首要靶点。

通路融合的 3,037 行里，58 行满足当前 `fused_fdr < 0.05`，其中方向一致 40 行、冲突 15 行、未定 3 行。实现先按规范化名称匹配，取各层 `padj`，层内 Bonferroni，再做 Fisher 合并和分层 BH。跨库同名、共享动物及相关组学会影响解释，已校正概率也不具备原始连续零假设 p 值的一般性质。建议现阶段将融合值用于探索排序，同时展示各层效应和校正值。要报告发现错误率，需验证所用检验及其随机化零分布。现有反应档案的校准表也明确将组别置换记为未运行。[融合实现](../../src/omicsweave/integration/modes/pathway_convergence.py) · [SciPy 合并检验假设](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.combine_pvalues.html)

正式运行时去掉 `--dry-run`。如果需要一个 IDE 可启动的脚本，可令它调用 `run_pipeline(root=项目路径)`，返回值逐实验提供 `run_dir` 和 `integration_dir`。流程已经能依次校验、跑单组学、把准确的源运行 ID 传给整合，再执行课题脚本。[Python 入口](../../src/omicsweave/core/pipeline.py)

**建议每个课题有稳定的结果根目录，由每次运行在其下创建独立子目录。** 现有键为 `project.yaml` 中的 `project.paths.results`，默认值为 `analysis_results`，相对路径以项目目录为基准，也接受绝对路径。例如在已有 `project:` 下加入 `paths: {results: D:/OmicsResults/dio_project}`。标准单组学和整合分别写入 `<结果根>/<实验 ID>/<运行 ID>/`，整合清单记录 `source_run`。现有 `export --output` 只指定这次导出的文件或目录。DIO 两个后处理脚本直接拼接 `analysis_results`，自定义根目录要覆盖整个 DIO 流程，需先完成下表 P0。

交付端有一个可见的版本问题。DIO 的 `analysis/key_results/tables.md` 文件头仍指向 11 月 3 日的单组学包和 11 月 4 日的整合包。用 11 月 18 日的两个准确 ID，把同一个脚本的输出定向到临时目录，成功得到 17 张 TSV 和 1 份 Markdown。固定的摘要目录无法告诉读者它是否对应刚完成的运行。此外，标准 `export` 只枚举组学及整合的 `tables/*.parquet`，而 QC、校准表、面板宽表和课题脚本在不同位置。脚本及事后导出的文件也缺少贯穿整个 pipeline 的清单。[统一导出](../../src/omicsweave/contract/export.py) · [阶段清单](../../src/omicsweave/core/run.py)

## 中文乱码的诊断与修复

逐文件严格解码两个课题的 `analysis_results/` 和 `analysis/` 下全部 1,479 份 CSV/TSV。1,330 份 CSV 中有 509 份带 UTF-8 BOM，149 份 TSV 均为无 BOM 的 UTF-8，其中 95 份含非 ASCII 字符。全部文件均能按 UTF-8（容许 BOM）读取，扫描未发现 U+FFFD。DIO 肝脏丙酮酸面板 `matrix_HFD_vs_LFD.tsv` 的 E2 是“与乳酸、丙氨酸的交换”，同名 XLSX 的 `matrix!E2` 完全一致。这个样本支持 Excel 打开文本时误判编码的解释。严格解码成功本身无法排除曾以错误编码读入、又另存为合法 UTF-8 的情形。

| 看到的现象 | 立即可用的处理 | 验证 |
|---|---|---|
| TSV/CSV 在 Excel 中乱码，UTF-8 读取时中文正确 | 优先打开同次导出的 XLSX。只有文本时，从 Excel 的“数据 → 从文本/CSV”导入，文件原始格式选 65001（UTF-8），TSV 选制表符，CSV 选逗号，标识符列按文本导入。 | 核对相同单元格的中文、希腊字母、行列数。 |
| 需要便于 Excel 打开的文本副本 | 对已严格确认的 UTF-8 文本，另存一份带单个 BOM 的 `.tsv` 或 `.csv`，保留原分隔符。可直接为原始 UTF-8 字节添加 BOM，避免重新解析时改变前导零、空值或数值精度。 | 去掉副本 BOM 后，字节与原 UTF-8 正文一致。 |
| XLSX、Parquet 或按 UTF-8 读出的字符串已经异常 | 定位最早出现异常的输入或导入步骤，用清洁源和明确编码重新生成新版本；来源确为 GBK/GB18030 时，仅在该输入边界严格解码。若出现替换字符或信息丢失，依赖原始文件或备份恢复。 | 对照源单元格；保留原文件与来源哈希。BOM 只能帮助识别编码。 |

样本表读取器已支持 UTF-8（有无 BOM）和带 BOM 的 UTF-16，并对其他字节报出行号。应优先统一的是面向读者的结果导出。[样本表读取](../../src/omicsweave/core/config.py) · [微软的 Excel UTF-8 打开方法](https://support.microsoft.com/en-us/excel/opening-csv-utf-8-files-correctly-in-excel)

## 建议的实施顺序和验收

| 优先级 | 交付目标 | 可复核的验收条件 |
|---|---|---|
| P0　一次运行对应一次交付 | 沿用现有 `pipeline` 与 `project.paths.results`。课题脚本接收实际 `run_dir`、`integration_dir` 和新增的交付目录。增加运行级索引，记录单组学与整合 ID、配置与脚本指纹、关键表、QC、图、导出文件及阶段状态。可将交付目录置于 `<结果根>/<实验 ID>/deliveries/<pipeline_id>/`，大文件通过索引引用。 | 默认路径、自定义绝对路径、含中文与空格的路径均可完成；两次运行能各自打开相应摘要。故意让一个脚本失败，索引能指出缺项；按确切来源续跑后生成完整交付。 |
| P0　统一表格编码与流程预检 | 标准导出、面板 TSV 和课题关键表共用读者导出规则。默认提供 XLSX 摘要，Excel 用 CSV/TSV 显式写 `utf-8-sig`；正式结果继续采用 Parquet。让 `pipeline --dry-run` 检查实际模式注册表以及已知输入前提。 | 同一行的“肝脏”、β、μ、¹³C、带前导零的 ID 在 Parquet、XLSX 与指定编码的文本导入中往返一致。当前 demo 配有 `sample_level`，预检报告 0 错误、0 警告，但模式选择器明确拒绝；增加覆盖该差异的测试，并提供可实际运行的合成示例。 |
| P1　默认输出无面板候选表 | 基于现有差异、融合和反应分级表生成各组织与比较的全量候选和简表。标明实体/库、效应与方向、单层和多层支持、检验背景、调整范围、QC、缺失或冲突原因，以及是否属于研究者面板。记录面板为预设或看过结果后选定。 | 空面板时照样产出通路与节点简表；能回查 DIO 面板外的 `RPI_c`。只有一层支持的通路仍可追溯，方向冲突清晰可见。只改展示面板时全局搜索范围稳定；改预期示踪剂规则时登记其对等级的影响。 |
| P2　校准发现结论 | 优先使用带物种、库版本和命名空间的通路 ID 对齐，记录仅名称匹配与无法映射的情况。明确检验族，保留原始和校正概率，按生物学个体及实验设计做同步分层置换，再以半合成信号、阴性对照与可比独立队列检验排序。复用现有诱饵、稳健性与复现工具。 | 报告零信号下的误报、注入信号回收率、单动物敏感性、方向一致性和置换分辨率。样本量或可交换性不足的分层明确标为探索性；同一批数据中事后选择的面板不充当独立验证。 |
| 后续可选　无先验模块探索 | 若课题确实需要已知库之外的结构发现，可在足量样本上另设共变模块或子网络发现，给出稳定性、成员和可追溯的注释，再设计独立验证。 | 对样本量、批次和分组混杂先做可行性判断；评估独立数据中的模块保留和可重复性。输出标为候选模块，生物学路径和因果方向另行验证。 |

复核时两个真实课题的 `all_tissues` 均通过预检，DIO 和 GLP-1RA 分别有 22 和 34 个警告，涉及样本量与参考标识等。运行了 pipeline、导出、面板、反应档案与整合五个测试文件，41 项测试通过，另有 32 项子测试通过。上述数目验证的是软件行为和已有输出；研究结论以相应队列的实验设计与证据等级为准。
